# Pilot checklist

A short plan for trying Wardmap on one ward before wider use.

## Before day one

- [ ] Backend created and the web app hosted ([setup.md](setup.md) steps 1-4).
- [ ] Your hospital and admin account created.
- [ ] The pilot ward added, with its beds laid out on the ward map.
- [ ] Accounts for the pilot team: one consultant, the residents (R6 to R1)
      and any rotators. Seniors can create their juniors' accounts.
- [ ] Each person has logged in once on their phone and added the app to
      their home screen.
- [ ] Check your hospital's rules on storing patient data in a cloud
      service, and pick the Supabase region accordingly.

## During the pilot (suggested 2 weeks)

- [ ] Admit every new patient on the pilot ward in Wardmap.
- [ ] Write daily progress notes and team tasks in it.
- [ ] Seniors use the **Juniors** tab on rounds.
- [ ] Keep the usual paper or system record alongside; Wardmap is not yet
      the official record.

## Review at the end

- Did anyone get stuck? Which screens were slow or confusing?
- Did the access levels match how the team really works?
- Spot-check a few patients' **History** tabs: is every change there, with
  the right person?
- List changes for the next version in the project thread; each one goes in
  as a pull request and a CHANGELOG entry.
